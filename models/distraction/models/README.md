# Shipped models (release 2026-10-19)

These files are committed so a fresh clone runs without the ~150 GB of training data or a GPU.
Every other file in this folder is git-ignored and regenerated by the scripts (see
[../README.md](../README.md) and [../docs/REPRODUCE.md](../docs/REPRODUCE.md)).

## Which file to use

| File | What it is | Use it for |
|---|---|---|
| `det_v2d_ir_512_ncnn_model/` | **Default.** YOLO26n phone / drink / food detector, trained on gray (IR) images, 512 px, FP32 NCNN | PC and Pi (`configs/pipeline.yaml`, `configs/profiles/laptop_webcam.yaml`) |
| `det_v2d_ir_512_det_aciq_mixed_ncnn_model/` | Same model, **INT8** (ACIQ, first layer + head kept FP32), 2.8 MB | Pi when speed matters (~20 % faster, same accuracy within noise) |
| `det_v2d_ir_512.onnx` | Same model, ONNX opset 11, raw head output `1x7x5376` (4 box + 3 class scores per anchor, NMS-free) | `detector.backend: onnx`; input for the Hailo-8 compiler (DFC) |
| `det_v2d_ir_512.pt` | Same model, PyTorch / Ultralytics weights | Fine-tuning, `scripts/eval_simple.py`, re-export |
| `det_v2h_fish_512_ncnn_model/`, `det_v2h_fish_512.pt` | det_v2d fine-tuned with simulated 160° fisheye + driver-ROI views | **First alternative to try on the real Pi fisheye camera**; thresholds phone 0.35, drink 0.55 |
| `yolo26n_pose_320_ncnn_model/` | Stock COCO YOLO26n-pose, 320 px, NCNN | Wrist keypoints for the texting rule (`phone_in_hand`) |
| `action_v2/` | **v2 phone model** (what the Pi stream runs): action classifier + two phone-in-hand checks, all INT8 NCNN, 1.6 MB each. See [v2 below](#v2-action-classifier--phone-checks-hybrid) | `scripts/stream.py --hybrid` (`scripts/hybrid.py`) |

The face landmarker is shared with the face subsystem: `../../face/models/face_landmarker.task`
(also in git). `hand_landmarker.task` (full mode only) comes from `python scripts/fetch_models.py`.

## det_v2d: model card

- **Architecture:** YOLO26n (2.5 M parameters, 5.9 GFLOPs), classes `0 phone, 1 drink, 2 food`.
- **Input:** 512 × 512 letterbox (pad 114), gray image copied to 3 channels, RGB, 0–1.
- **Thresholds (tuned on 10 validation drivers):** phone 0.40, drink 0.45, food 0.40.
- **Training:** COCO weights → 7 epochs on Open Images + SynDD + EBDD (416 px) → 35 epochs on the
  full mix (det_v2b, 416 px) → **15 epochs gray-only at 512 px, lr 0.002** (det_v2d).
  53,889 training images: SynDD infrared mirror-view video (69 drivers, split by driver
  49 / 10 / 10), Open Images V7, Roboflow DMS_Project v2 and ADMS_FINAL_3 v1, EBDD, plus 7,010 gray
  copies and 7,913 copies with a real hand pasted over the phone. Details:
  [../docs/DETECTOR_V2.md](../docs/DETECTOR_V2.md), [../docs/DATA.md](../docs/DATA.md).
- **Rules on top** (`configs/rules.yaml`, `mode: simple`): phone box in ≥ 60 % of the last 1 s →
  phone ALERT; drink / food box over the lower face → drinking / eating ALERT; head ≥ 15° down from
  the driver's baseline + a wrist low and central for 2 s → `phone_in_hand` WARNING, 3 s → ALERT.

### Results (alert level, live geometry, 10 frames per second)

| Test | Phone at right ear | Phone at left ear | Texting | Drinking | Phone false alarms |
|---|---|---|---|---|---|
| SynDD test, 10 unseen drivers (scored once) | 80 % | 100 % | 41.5 % (46 % with warnings) | 90 % | 0 / h |
| SynDD validation, 10 drivers | 100 % | 100 % | 52.5 % | 95 % | 5.2 / h |
| 5-fold by driver, 59 drivers (shorter recipe), mean (range) | 89 % (73–100) | 97 % (88–100) | 65 % (58–75) | 66 % (52–79) | 9.0 / h (2.8–22.4) |
| 3MDAD, 50 unseen drivers, gray-converted colour | 80 % | 92 % | 96 % right hand / 16 % left (phone hidden) | 68–80 % | 8 % of normal clips |
| DAD, 3 unseen drivers, real IR, front camera | 4 / 5 calls | | 5 / 6 | 2 / 2 | **69 / h** (steering wheel read as a phone) |

Eating: 0 % everywhere. Food is almost never visible in these views; treat eating as unsupported.
False alarms depend strongly on the camera position. Before trusting the numbers on a new car,
record 20–30 min of normal driving with that camera (see
[../docs/IN_CAR_TEST_PROTOCOL.md](../docs/IN_CAR_TEST_PROTOCOL.md)).

### Speed (laptop CPU, NCNN)

| | ms per frame (1 thread) | ms (4 threads) | size |
|---|---|---|---|
| FP32 | 49.7 | 28.3 | 9.3 MB |
| INT8 mixed | 38.1 | 22.6 | 2.8 MB |

Full simple-mode pipeline on the laptop: ~25 FPS without pose, pose adds 8–11 ms per frame.
Raspberry Pi 5 numbers: still to be measured with all models running.

## v2: action classifier + phone checks (hybrid)

Instead of finding the phone as a box, v2 names what the driver is doing from a crop around the
face (face mesh), then confirms a phone where it should be. Code: `../scripts/hybrid.py`
(+ `hybrid_alerts.py`), run with `scripts/stream.py --hybrid`. Training, evaluation and every
decision: [../action_v1/](../action_v1/) (`REPORT.md`, `REPORT_v2.md`, `DECISIONS.md`).

| File | Model | Input | Output |
|---|---|---|---|
| `action_v2/action_n224_int8_ncnn_model/` | YOLO26n-cls, INT8 (KL) | upper-body crop, 2.5 × face size, 224 px gray | normal, call, texting, drinking, eating, hand_on_face, other |
| `action_v2/phone_ear_n128_int8_ncnn_model/` | YOLO26n-cls, INT8 (KL) | crop just outside each ear, 1.2 face widths, 128 px | phone_in_hand / empty_hand |
| `action_v2/phone_lap_n128_int8_ncnn_model/` | the ear model fine-tuned on lap crops, INT8 (KL) | square 2.5 × face size under the chin, 128 px | phone_in_hand / empty_hand |

- **Alerts:** CALL when the action is `call` in ≥ 70 % of the last 2 s **and** the mean ear phone
  probability > 0.5; TEXTING when the action is `texting` in ≥ 70 % of 1.5 s **and** the mean lap
  phone probability > 0.4. A hand on the face never raises a phone alert.
- **Results vs det_v2d (same clips; FA/h = false alerts per hour on normal + hand-on-face):**
  SynDD test calls 37/39 vs 34/39, texting 18/41 vs 14/41, FA 0 vs 0; 3MDAD calls 30/30 vs 24/30,
  texting 24/30 vs 17/30, FA 19.6 vs 14.2; DAD real IR calls 5/5 vs 4/5, FA 3.6 vs 79.2.
  INT8 costs < 0.3 points of accuracy. Full tables: `../action_v1/REPORT_v2.md`.
- **Speed:** ~15 ms per frame of model time on the Pi 5 (estimate scaled from det_v2d's measured
  45 ms); the Pi stream runs at the camera's 30 FPS with face mesh + drowsiness.
- The Pi stream runs v2 with `--no-detect` (no box detector), so drinking / eating alerts are off
  there; REPORT_v2 proposes det_v2d boxes for those two.
