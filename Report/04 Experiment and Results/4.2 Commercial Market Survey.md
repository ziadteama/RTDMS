# 4.2 Commercial Market Survey and Product Benchmarking

↑ [[04 Experiment and Results]]

Commercial Driver Monitoring System products from Smart Eye, Seeing Machines, Cipia, Jungo, oToBrite, Valeo, Netradyne, and Motive indicate the current market direction: camera-based in-cabin sensing, active driver alerts, event recording, cloud analytics, and fleet integration. Public pricing is usually not posted because most vendors sell through quotations, demonstrations, or partner channels. Therefore, these products are more valuable as functional benchmarks than as directly purchasable student hardware.

For the prototype, the most practical route is to use Raspberry Pi 5 as the base compute board, supported by Raspberry Pi AI HAT+ 26 TOPS for computer-vision acceleration. IR or NoIR camera hardware is preferred for low-light drowsiness detection, while the MAX30102 module provides a practical wristband-based HR/HRV sensing path.

## 4.2.1 Survey of Commercial DMS Products

These products are important benchmarks because they show the features expected in a mature DMS stack, including driver-facing cameras, IR support, real-time fatigue and distraction classification, alerting, event capture, fleet portals, and compliance-oriented reporting.

### 4.2.1.1 Product Brief Descriptions

- **Smart Eye AIS:** A commercial-grade driver monitoring system using IR cameras and embedded AI to detect drowsiness, distraction, and impairment in real time.
- **Seeing Machines Guardian Gen 3:** A fatigue monitoring solution combining computer vision and cloud analytics for continuous real-time driver monitoring and alerts.
- **Cipia Fleet Sense:** An AI-based system integrated with telematics, tracking gaze, head pose, and driver behaviours such as phone use and seatbelt compliance.
- **Jungo VuDrive:** A vision-based monitoring platform with cloud analytics focusing on distraction detection, event recording, and driver scoring.
- **oToBrite Vision-AI DMS:** An OEM-oriented system using IR imaging and 3D facial tracking for robust monitoring under challenging conditions.
- **Valeo DMS:** An automotive-grade embedded system integrated into vehicle ECUs for continuous driver attention monitoring.
- **Netradyne Driver-i:** A fleet safety platform combining edge AI with cloud-based analytics for real-time alerts and behaviour tracking.
- **Motive AI Dashcam:** A dual-facing AI dashcam that integrates driver monitoring with telematics and communication features.

## 4.2.3 Final Market-Based Hardware Recommendation

Based on the market survey and the prototype constraints, the selected hardware stack is Raspberry Pi 5 (8GB), Raspberry Pi AI HAT+ 26 TOPS, Pi IR camera 5MP 160-degree module, and MAX30102 wristband sensor module. This combination provides a balanced trade-off between cost, implementation feasibility, real-time computer-vision capability, low-light cabin monitoring, and wearable physiological sensing.

> [!info] Figure 4-3 — Raspberry Pi 5 (8GB) Edge Computing Board *(see original .docx)*

This component was selected as the central processing unit because it provides a practical embedded-computing platform for camera acquisition, sensor communication, local event logging, and real-time control logic. Its Raspberry Pi ecosystem support, GPIO/CSI interfaces, and local availability make it suitable for an RTDMS prototype.

> [!info] Figure 4-4 — Raspberry Pi AI HAT+ 26 TOPS Accelerator *(see original .docx)*

This accelerator was selected to support real-time computer-vision inference while reducing the processing load on the Raspberry Pi 5. The 26 TOPS Hailo-based acceleration is appropriate for the visual modules required by the prototype, including eye-state analysis, head-pose estimation, gaze monitoring, and phone-use detection.

> [!info] Figure 4-5 — Pi IR Camera 5MP 160-Degree Module *(see original .docx)*

This camera module was selected because driver monitoring must remain usable under variable cabin lighting, including low-light and night-driving conditions. The 160-degree field of view improves coverage of the driver face, head position, and upper-body region while keeping the prototype cost within a reasonable range.

> [!info] Figure 4-6 — MAX30102 Wristband Sensor Module *(see original .docx)*

This sensor module was selected for the physiological-monitoring layer because it provides a compact and affordable PPG-based path for heart-rate measurement and HRV-related analysis. It is suitable for wristband prototyping and can support fatigue or stress confirmation alongside the camera-based detection modules.
